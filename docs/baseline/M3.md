# M3 等待图死锁检测与解除

> 状态：**实现完成，夜跑验证通过**（分支 `m3-deadlock-detection`）。OpenSpec 变更：`openspec/changes/m3-deadlock-detection/`。
> 本文的对照数据与场景结果全部来自夜跑报告 `docs/baseline/nightly/`，没有手填的数字。

## 做了什么

- **死锁检测改为等待图找环**（`robot_tasks/traffic_deadlock.*`，纯函数 + GoogleTest）：节点是车，"车 A 等的资源被车 B 占着或暂扣着"即 A → B。rolling 下一辆车等一组资源（路段 + 路口），两样可能被两辆车占着，所以一个节点最多两条出边（二开计划 5.4 节假设的是一条），找环用三色 DFS，一次检测返回互不相交的全部环。每次有申请新进入等待时检测一次，1 Hz 定时器再全量检测一次。
- **whole_route 也能检出**：whole_route 被拒的申请不排队，但记成 6 秒有效的"重试等待"计入等待图。M2 里 whole_route 2～4 分钟停摆的那种互等，现在能被看见、能被解开。
- **解除**：环上选让路车（优先级最低 → 到 `goal_station` 剩余路程最长 → 车辆号最大）；能绕开环上他车占用的资源到达目的地就改道（`reroute`），否则退到最近的空闲避让点停 5 秒（`backoff`）；同一组车 30 秒内第三次成环或找不到避让点就全部暂停（`pause`），运维对其中任一辆车调用 `/v2/clear_traffic_reservation` 后恢复。指令发在新话题 `/traffic/yield`（`TrafficYield.msg`）。参数 `traffic_deadlock_resolution_enabled:=false` 只检测不解除。
- **`/v2/detect_traffic_deadlock`**：名字、类型不变，语义改为报告当前等待环（`mission_ids` 里是环上车辆号）。"两车只是共用站点"不再报死锁。
- **`/traffic/state`** 追加死锁统计：检测次数、检出环数、当前环上的车、最近一次解除的动作 / 让路车 / 耗时、已解开环数、单次检测耗时（最近、最大）、按动作分类的解除次数。
- **`/v2/request_route_segment`** 请求追加可选字段 `goal_station`；车队代理和任务中枢自己的站点运输都会填。

## 补规格时记下的三处隐患怎么处理的

| 隐患 | 处理 | 对外影响 |
| --- | --- | --- |
| 占用者在 whole_route 下是任务号、rolling 下是车辆号 | whole_route 下站点运输入队锁路也用执行车辆的车辆号占用；任务号只留在 `route_locks_by_mission` 里记"这张工单锁了哪些资源"。同一辆车多张工单共用的资源，等最后一张结束才放 | `/traffic/state`、占用查询里不再出现任务号占用者；解封失败消息由 `reserved by mission: X` 改为 `reserved by: X` |
| 路段锁命名在核心、代理、压测脚本里各写一份 | 资源号只在 `traffic_reservation.cpp` 生成。代理记下授予应答里的资源号，到站后释放"持有的资源中除当前路口外的全部"；封路集合和绕行集合按"无序站点对"存，由资源号解析。压测脚本解析交通状态里的资源号，不再拼名字 | 无（资源号格式本身没变，规格里写明了格式） |
| 拿不齐整组路段的高优先级等待者会被一直插队 | 等待超过 `traffic_wait_starvation_s`（默认 20 秒）的等待者，它所需资源中已空闲的部分暂扣给它：排在它后面、优先级不高于它的车拿不到这些资源，新申请撞上暂扣也排队。暂扣不写进路权表，安全判定不受影响；被暂扣挡住的车在等待图里指向暂扣者 | 长期饿着的车不再被低优先级车插队（**只对 rolling 生效**，见对照表下 2026-11-22 的补充）；对吞吐的影响由夜跑阶段 5 给出 |

## 路网 `workshop_2way`

`workshop` 全是单向边、最短有向环 8 站，rolling 下不会成环，在上面测检出次数永远是 0。`workshop_2way` 站点和停车位与 `workshop` 相同，改了两处：横穿 jn_s–machining–jn_n 和外环 jn_sw–receiving、jn_n–packing 改为双向（两车对向）；新增单向斜边 jn_se → machining，与 jn_s → jn_se、machining → jn_s 组成 3 站环（三车成环）。夜跑阶段 5 的对照矩阵跑在它上面，M2 的 `workshop` 数字仍可复现。

## 已知限制

- **6 台 rolling 仍偶尔兜底暂停**：第一轮、第二遍各 1 次（第三遍 0 次），4 台及以下 0 次。现场（第一轮第 963 秒）：robot_2 在 jn_n 等 machining，robot_3 在 machining 等 jn_n，两车的其他出口都被直接或间接在等它们的车占着，改道、退避都没路可走，只能暂停。压测里没人解冻，第一轮此后再没完成任务，6 台 rolling 吞吐因此只有 66（第二遍暂停发生在第 1659 秒，影响小）。可能的改进是让环外的上游等待者先退，留给后续里程碑。

- 任务中枢自驱的站点运输（Gazebo 演示里的车）不执行改道和退避：被选为让路车时只撤等待，下一次按原路重申请；反复成环由兜底暂停接住。轻量仿真里的车都是代理，不受影响。
- `deadlocks.csv` 的逐次细节取自 1 Hz 的交通状态，同一秒内解开两个环时中间那次的细节会漏（`skipped_details` 列记数），计数不漏。
