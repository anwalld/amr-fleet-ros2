# Design

涉及 robot_interfaces_fleet、robot_tasks 的车队服务、robot_simulation 的任务代理以及 M4 调度台。实施时以合入 Ops/Alarm 的基线集成；保留原下单、查询和状态上报服务的类型。

建议新增定向控制服务和代理确认通道。控制方记录请求 ID、任务 ID、分配车辆与执行代次，代理按同一元组确认；同请求重试返回已知结果，迟到命令及旧进度回报不得覆盖终态。应答超时显示结果未知并按原请求查询，断线或重启未对账时禁止自动起步。恢复须同时满足目标匹配、车队停止状态新鲜且已解除、路权仍有效。

在代理运动积分与任务阶段推进前检查停止条件。暂停时冻结路径进度和装卸计时；取消后以独立的车辆等待调度状态屏蔽空闲回位和自动领单。新增显式移车入口，绑定车辆、当前等待代次和目的站，验证急停与路径后从实际停点续行，到达原段出口才释放车身已离开的资源。rolling 与 whole_route 均保守保留既有占用，移动交接不得产生保护空窗。

轻量运动学仿真采用新鲜位姿样本确认停稳：至少连续 1 秒、相邻间隔不超过 0.2 秒，位置相对窗口起点偏移不超过 1 毫米，期间无运动积分。缺样保持处理中并报告观测不可用。验收从独立位置流核对同一窗口，加入正常行驶正对照、冲突申请和另一辆车继续运行的对照。以上数值为仿真设计参数，实施时实测。

## 重启边界与合并验收

探索对比了从本地快照恢复运动、从实时权威状态重建、以及在证据不足时冻结。里程计、路权、队列和下层目标的生命周期不同，旧进程记录不能单独证明当前状态。先用持久运行标记识别重复启动，对已经使用过的状态路径或写入错误按待对账处理，禁止自动继续。车队代理进入驻留，调度端转发查询结果。 合并仿真环境需显式为每个节点传入独立持久路径，首次使用空路径项，重启复用同一路径。换路径前须核对车辆、占用和任务，再通过显式调度恢复。持久标记仅用于停止保护，完整运行态重建另待实现。

本变更整栈专项进入合并夜跑，单项本地验证只使用隔离 ROS 域。共同跑实际启动后按项目规则绑定全部参测变更并核对终态证据。

## 调度中枢重启后的查询语义

代理单独重启时已有 `RECOVERY_REQUIRED` 答复。调度中枢单独重启时，旧任务索引已空，按当前查询流程可能误将旧任务判为不存在，还可能接受新派单。对比了继续按空索引处理、从请求自带任务号猜配属、显式返回待对账。采用待对账，转发入口回显原任务标识、执行代次和修订号，拒绝重启未对账时的新车队派单和状态写入。原有服务格式保持。

后续先核对活着的代理及交通权威的实际位姿、占用与旧单归属，再对照持久的执行代次与回执。只有得到足够信息才能恢复状态。旧命令查询可返回未知；禁止把未知结果当作已取消或允许另一辆车占用。

### 取消后驻留的重启对账

已停稳且取消的轻量仿真车辆可重建驻留。代理保存停车位姿、占用、任务执行标识及取消修订，持有检查点目录的独占锁。重启时只读取得当前地图、调度端任务终态和交通快照。停车记录须匹配车辆和路权模式，当前路权快照来自同一发布端、原占用仍归本车，原任务仍由本车持有且为 CANCELED，才恢复驻留和取消回执。该位姿由轻量仿真代理产生，适用范围为代理本身是位姿源的模式。显式移车前先失效停车记录。活动任务、运动中中断、缺失记录和其他不一致均继续锁住。合并验收需要分别证明驻留重建、原回执查询、旧路权缺失时保持禁止，以及显式移车才解除驻留。

### 已确认暂停的活动任务

探索比较了重走整单、只恢复可证明的执行断点、以及一律阻断。轻量仿真中位姿由代理独占产生，已停稳的普通行驶段和站点装卸可保存断点。保存原执行、暂停修订、目标与路径进度或装卸剩余时间。复用同一任务与交通权威，核对实时 PAUSED 终态、归属、站点和原占用，恢复为暂停态。恢复只允许显式 RESUME，且在解除停车前先作废旧断点，避免运动中退出后重放旧位姿。正在避让、未确定停稳、无可靠路权和未匹配的任务继续阻断。旧的取消驻留记录保留可读性。

### 调度中枢进程重启

探索对比了从代理重新推断任务分配、把中枢的可见状态和回执留存、以及继续只返回未知。重启后的空表不能代表旧路权或执行终态。中枢在配置检查点时以独占文件锁管理目录，接收远程分配与状态更新时先保存，再确认操作。转发代理应答前原子保留已确认回执，按原任务、执行标识、修订查询。尚未收到代理确认的记录不伪造回执。重启后可读回任务分配和已确认回执，控制写入与交通授权在实时权威确认前保持阻断。
