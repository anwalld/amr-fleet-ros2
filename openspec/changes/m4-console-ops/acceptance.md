## Ops 新增场景的预期结果

Core 没有这些调度台写操作的实测行。首次完整通过的 Ops 夜跑将按下表存档实际结果，后续再按用例 ID 逐项比较。每个场景由调度台入口触发，证据至少包含目标标识、请求次数、后端回执和独立观测的状态。成功与冲突场景使用可控制初始状态的仿真用例。

| 用例 ID | 操作 | PASS 判据 |
| --- | --- | --- |
| ops-ui:workflow_submit | 提交目录工作流 | 受理后返回子任务编号，使用原订单号查询到对应工作流。 |
| ops-ui:workflow_control | 对同一订单暂停、恢复、确认取消 | 各请求的订单号和是否包含运行中子任务与界面选择一致。查询验证目标订单 paused 先真后假。取消回执核对 canceled_mission_ids 与 active_cancel_requested，再用快照确认已取消的排队项移除。运行中子任务收到取消请求时另查其实际结束事件。工作流查询可返回 UNKNOWN。 |
| ops-ui:fleet_submit_remote | 提交车队搬运并派发给车辆代理 | 回执显示任务号和分配车辆，快照出现同一远程任务并跟踪到终态。 |
| ops-ui:fleet_submit_local | 提交车队搬运并派发给本地任务中枢 | 用返回的任务中枢编号跟踪队列、活动任务或事件，得到对应终态。 |
| ops-ui:route_block | 封路、解封，并尝试封住已占用路段 | 地图观察到封锁及解封。占用时服务拒绝，原占用保持，界面显示原因。 |
| ops-ui:fleet_enabled | 停用、启用指定车辆 | 快照中同一车辆的启用标志按顺序变化。请求只置启用更新标志。 |
| ops-ui:clear_match | 预览并清理当前占用 | 确认范围与后端匹配，释放所列资源、解除所列暂停，随后按原规则补授予。 |
| ops-ui:clear_owner_conflict | 预览后改变占用者，再确认旧预览 | 后端返回冲突，无清理、解除暂停或额外补授予，界面刷新且等待再次确认。 |
| ops-ui:clear_scope_conflict | 保持占用者，改变其资源集合或暂停组，再确认旧预览 | 后端返回冲突，无清理、解除暂停或额外补授予，界面刷新且等待再次确认。 |
| ops-ui:submit_timeout | 用受控仿真夹具延迟写操作的服务回执 | 3 秒后界面报告结果未知且未自动重提，读取更新继续；匹配到同一订单或任务后更新观测结果。 |

随阶段 7 执行 Ops 操作验收，单独启动或重置仿真用例，保留原来的无人操作 300 秒冒烟口径。产出独立的 `console_ops_results.tsv`，使用下节规定的五列格式并按键关联证据，每个用例恰好一条。阶段报告应引用它和原始日志，列出缺失、重复、FAIL、SKIP 与用例证据。全部预期用例 PASS 才算 Ops 专项通过。首次按此口径通过后，实施任务将结果与来源写入 `docs/baseline/M4-ops.md`，后续固定用这份结果作 Ops 逐项回归对照。

## 夜跑取证与结果归档

- 使用 QtTest offscreen 的真实窗口和 RosBridge 发起被测动作。复用 `robot_wait.sh`、`check_workflow_pause_resume.sh`、`check_workflow_cancel.sh`、`check_traffic_deadlock_pause_clear.sh` 的就绪条件、造景方法和后端断言。夹具调用只用于布置状态与独立观察，结果日志分别标明夹具与调度台的请求。
- 本地与远程搬运分别在隔离栈设置唯一合格的本地或远程车辆，核对分配号后继续。冲突用例在预览和确认之间用夹具完成状态切换，分别验证资源集合变化和暂停组变化。超时用例用仅针对目标服务的延迟应答夹具，保留快照和里程计读通路。各用例在停止或超时退出时清理自己启动的栈。
- 对无人操作的服务边界，在调度台客户端实际发送位置记录按服务名分组的计数。外部压测下单和 ROS 框架自身的监控通信不计入调度台业务请求。结合应用发布者检查，验证三个读取服务均有请求、其余业务请求及业务话题发布为零。
- 使用验收重整的 `acceptance_compare.py` 读取既有阶段 3 格式，显式传入固定参考和用例映射。保留逐夜对照。Ops 阶段 7 复用其现有结果表结构 `suite, case, kind, status, seconds` 和完整性检查，suite 为 `ops-ui`，组合键对应上表。Ops 使用自己的登记表（含 suite、case、栈、预算字段）及映射输入，独立调用比较器；首轮可无 Ops 历史结果。表中 kind 与实际栈一致。超时夹具单列栈类型。在本轮报告中按键关联独立日志，记录被测版本、ROS 域、请求标识、目标、应答和观测。证据文件缺失或不能证实断言时该项失败。
- 保存首个完整通过的原始 `console_ops_results.tsv` 为 `docs/baseline/m4_ops_results.tsv`，在 `M4-ops.md` 记录来源、版本和文件摘要。后续运行只读引用。阶段 7 汇总冒烟与 Ops 两个退出码，任一失败或必需证据不全则阶段失败；阶段 8 报告保留二者结果。退出码外还要验证 TSV、每项日志及断言齐全，避免仅打印 PASS 便通过。Dagu 接入时由同一个判定入口读原始结果，干跑只核对接线与输入。

实施时从包含 Core 的主线取产品代码。若验收重整工具尚在独立分支，夜跑按已核验的提交组装脚本、用例表、映射和参考结果并记录清单。阶段 3 固定对照前核对旧键到登记表的覆盖，只允许有明确映射和理由的删除。沿用比较器处理当前表的字段、栈和结果，另外检查每个 Ops 日志的业务断言。
